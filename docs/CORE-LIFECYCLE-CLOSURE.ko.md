# Core 종료 경로와 기록 보강 설계

상태: 합의됨, 구현 완료(2026-10-03, `ui-projection` v9)  
근거: 2026-10-01~03 데스크톱 UI 수동 QA(S0~S4)에서 드러난 Core 공백

## 1. 판단 기준

Core를 바꿀지는 다음 두 단계로 판단한다.

1. **기록할 것인가**: 이미 기록된 사실에서 계산할 수 없는 새 사실이면 Core에 기록한다.
2. **Core가 강제할 것인가**: 그 사실이 실행 허용(admission), 검증 유효성, 달성 판단에 영향을 주면 Core 규칙으로
   강제한다. 그렇지 않으면 기록만 하고 화면에서 보여 준다.

이미 기록된 사실에서 계산할 수 있는 정보(예: "최근 실행 실패" 표시)는 Core가 아니라 화면이나 `ui-projection`에서 계산한다.

## 2. 종료 경로

세 기능은 같은 원칙을 따른다: **지우지 않고, 결정자와 이유를 남기고, 되살리지 않는다.** 다시 진행하려면
새 접근안이나 새 목표를 만든다. 이미 진행 중인 실행은 자동으로 취소하지 않으며, 그 결과는 계속 기록할 수 있다.

| | 접근안 닫기 | 과제 중단 | 목표 그만두기 |
|---|---|---|---|
| 상태 | Proposal `closed` | Goal `stopped` | Aim `abandoned` |
| 기록 | 종료 종류(`declined`·`withdrawn`), 결정자, 이유 | 결정자, 이유 | 결정자, 이유 |
| 가능한 때 | `open`인 Proposal | `committed`·`active`·`verifying` | `open`인 Aim |
| Core가 막는 것 | 과제 확정, 수정 | 새 실행, 검증 시작, 검증 판단 | 접근안 생성·확정, 하위 과제의 새 실행, 달성 평가 |
| CLI | `proposal-close` | `goal-stop` | `aim-abandon` |

- 목표를 그만둘 때 하위 접근안과 과제를 자동으로 닫지 않는다. 실행 허용 단계에서 목표의 상태를 조회해 막는다.
  이는 목표 일시 중지가 하위 과제에 보류를 복사하지 않는 기존 방식과 같다.
- 중단된 과제를 선행 과제로 둔 과제는 계속 실행할 수 없다. Core는 자동으로 연결을 바꾸지 않고, 화면이 이 사실을 알린다.
- 목표 "대체됨"(superseded)은 이번 범위에서 제외한다. 필요해지면 "그만두기 + 새 목표 + 연결"로 추가한다.

## 3. 기록 보강 (기록만 하고 강제하지 않음)

- **접근안 제안자**: `proposal-create --actor`로 제안자를 기록한다. 예전 기록은 "기록 없음"으로 읽는다.
  접근안 새 버전의 제안자는 수정한 사람이다.
- **실행 보류 사유**: `goal-hold-add --actor --reason`으로 결정자와 사유를 기록한다. 새 명령에서 사유는 필수다.
  예전 보류 기록은 "사유 기록 없음"으로 읽는다.

## 4. 구조 규칙 (Core가 강제)

- 과제는 자기 상위 과제(그 위의 상위 포함)를 선행 과제로 가질 수 없다. 상위 과제는 하위 과제가 끝나야 검증할 수
  있으므로, 이 연결은 서로를 기다리는 교착을 만든다. 같은 이유로, 이미 선행 과제인 과제를 상위 과제로 연결하는 것도 거절한다.
- 접근안과 과제의 관계는 1:1을 유지한다. 하나의 접근안에서 여러 과제가 필요하면 접근안을 나누거나 상위·하위 과제로 나눈다.

## 5. 예전 기록과의 호환

Journal은 재시작할 때 기록된 명령을 다시 실행해 상태를 복원한다. 새 규칙(보류 사유 필수, 상위 계열 선행 연결 거절)은
**새로 들어오는 명령에만 적용**하고, 예전 기록을 복원할 때는 적용하지 않는다. 그래야 규칙이 생기기 전에 기록된
journal도 그대로 열린다. 새 필드가 없는 예전 이벤트는 "기록 없음"으로 읽는다. SQLite 스키마 변경은 필요 없다.

## 6. 화면

- 접근안 화면: `채택하지 않음으로 닫기`(종료 종류와 이유).
- 과제 화면: 실패 후 네 번째 선택지 `이 과제 그만두기`, 과제 화면 아래 `과제 그만두기`.
- 목표 화면: `잠시 멈추기`(되돌릴 수 있음)와 `이 목표 그만두기`(종결)를 나란히 둔다. 일시 중지 중에는 `다시 진행`을 보여 준다.
- 실행 보류 추가 시 사유를 받고, 보류 영역과 그래프에 사유를 보여 준다.
- 접근안에 제안자를 보여 준다.
- 닫힌 접근안, 중단된 과제, 그만둔 목표는 흐리게 표시하고 새 행동을 제안하지 않는다.
- `ui-projection`은 위 기록 필드를 노출하도록 버전을 올린다.

## 7. `next`의 변화

- 진행 중이 아닌 목표(달성됨, 그만둠)의 과제에는 새 행동을 제안하지 않는다.
- 중단된 과제에는 진행 중이던 실행의 결과 정리만 제안한다.
- 열린 접근안이 없고 살아 있는(중단되지 않은) 과제도 없는 진행 중 목표에는 새 접근안 추가를 다시 제안한다.
