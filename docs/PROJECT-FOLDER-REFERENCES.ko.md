# 프로젝트 폴더, 참고 문서 링크, 관찰 근거 첨부 설계

상태: 합의됨, 구현 완료(2026-10-04, `ui-projection` v10)
근거: 2026-10-03~04 세션 dogfooding 준비 논의

## 1. 목적

Goal Loop로 이 저장소의 개발을 진행하려면 다음 세 가지가 필요하다.

1. 세션이 저장소 안에서 명령을 실행하면 별도 지정 없이 그 프로젝트의 기록을 사용해야 한다.
2. 목표, 접근안, 과제에서 설계 문서나 memory 모듈 같은 참고 문서를 가리킬 수 있어야 한다.
3. 검증자가 관찰 근거의 본문만 보고 판단하지 않도록, 관찰에 사용한 로그 같은 자료를 함께 남길 수 있어야 한다.

## 2. 판단 기준 적용

`docs/CORE-LIFECYCLE-CLOSURE.ko.md`의 두 단계 기준을 그대로 적용한다.

| 기능 | 기록하는가 | Core가 강제하는가 |
|---|---|---|
| 프로젝트 폴더 | journal 기록이 아니다. 저장 위치에 관한 규칙이다 | 해당 없음 |
| 참고 문서 링크 | 기록한다. 어떤 문서를 참고했는지는 다른 기록에서 계산할 수 없다 | 강제하지 않는다. 실행 허용, 검증 유효성, 달성 판단에 영향을 주지 않는다 |
| 관찰 근거 첨부 | 기록한다. 파일 이름, 크기, SHA-256을 관찰 근거와 함께 남긴다 | 형식만 검사한다. 파일이 바뀌거나 사라져도 검증 판단을 자동으로 무효로 만들지 않는다 |

## 3. 프로젝트 폴더

memory_tool이 `.memory/`를 프로젝트 안에 두고 상위 폴더로 올라가며 찾는 방식을 따른다.

```text
<프로젝트 폴더>/
  .goal-loop/
    .gitignore           ← 내용은 "*". 폴더 전체가 Git 관리 대상에서 빠진다
    journal.sqlite3      ← 이 프로젝트의 기록
    artifacts/<sha256>/<원래 파일 이름>   ← 관찰 근거 첨부 복사본
```

- `goal-loop project-init [폴더]`가 위 구조를 만든다. 이미 있으면 그대로 둔다.
- journal은 바이너리 SQLite이고 WAL 보조 파일도 생기므로 Git으로 관리하지 않는다. `.goal-loop/.gitignore`가 스스로 폴더를 제외하므로 프로젝트의 `.gitignore`를 고칠 필요가 없다.
- 클라우드 동기화 폴더(OneDrive 등) 안에 두면 동기화 프로그램이 쓰기 도중의 파일을 복사해 DB가 손상될 수 있다. 문서와 화면에서 경고한다.

### DB를 찾는 순서

1. `--database <파일>`
2. `--workspace <이름|id>` (데스크톱 앱 등록부)
3. `--project <폴더>`
4. 환경 변수 `GOAL_LOOP_DATABASE`
5. 현재 폴더에서 상위로 최대 10단계까지 올라가며 찾은 첫 `.goal-loop/journal.sqlite3`
6. 사용자 공용 DB(`%LOCALAPPDATA%\GoalLoopTool\goal-loop.sqlite3`)

DB 파일이 `.goal-loop` 폴더 안에 있으면, 그 폴더의 부모를 **프로젝트 루트**로 본다. 따라서 어떤 방법으로 DB를 지정하더라도 프로젝트 기록이면 프로젝트 루트를 알 수 있다. `goal-loop where`는 사용 중인 DB, 프로젝트 루트, 첨부 폴더, DB를 찾은 방법을 보여 준다.

### 데스크톱 앱

- 「프로젝트 폴더 열기」로 폴더를 고르면 앱이 `project-init`을 실행하고, 등록부에 `{id, name, project, database}`를 추가한다.
- 폴더 기반 프로젝트를 앱에서 삭제하면 **등록만 해제**하고 파일은 지우지 않는다. 앱이 만든 폴더 없는 작업 공간은 지금처럼 DB 파일까지 삭제한다.
- 폴더 없는 작업 공간도 계속 열 수 있다. 다만 상대 경로 링크는 쓸 수 없다.

## 4. 참고 문서 링크

링크는 **지금 살아 있는 문서**를 가리킨다. 문서 내용이 바뀌는 것은 정상이며, 링크는 언제나 최신 내용을 보여 준다.

- 대상: 목표, 접근안, 과제
- 위치: `http(s)://` URL 또는 파일 경로. 프로젝트 루트 안의 파일은 루트 기준 상대 경로(`/` 구분)로 저장하고, 루트 밖의 파일은 절대 경로로 저장한다. `#앵커`는 그대로 보존한다.
- 추가할 때 파일이 존재하는지 확인한다. 오타로 깨진 링크가 생기는 것을 막기 위해서다.
- 추가와 제거를 각각 이벤트로 남긴다. 제거된 링크는 이력에만 남는다. 닫힌 접근안이나 중단된 과제에도 링크를 붙일 수 있다.
- **링크는 판정 기준을 대신하지 않는다.** 완료 기준은 버전마다 고정되지만 링크가 가리키는 문서는 바뀐다. 판정에 필요한 조건은 완료 기준 본문에 적는다.

CLI:

```powershell
goal-loop reference-add goal-3 docs/PERSISTENCE-CONTRACT.md --label "저장 계약" --actor "claude"
goal-loop reference-remove reference-2 --actor "owner" --reason "다른 문서로 대체"
```

## 5. 관찰 근거 첨부

첨부는 **그때 관찰한 내용 그 자체**를 보존한다. 검증자가 본 자료와 나중에 열리는 자료가 같아야 하므로 복사본을 저장한다.

- 관찰 근거를 기록할 때만 붙인다(`evidence-record … --attach <파일>`, 여러 번 사용 가능). 판정 뒤에 자료를 보태면 검증자가 보지 않은 자료가 근거에 섞이므로, 나중에 보탤 자료는 새 관찰 근거로 기록하거나 관찰 근거 정정 흐름을 사용한다.
- CLI가 파일을 `artifacts/<sha256>/<원래 이름>`에 복사한 뒤 기록한다. 같은 내용은 한 번만 저장된다. 원래 이름을 유지해야 기본 프로그램으로 열 수 있다.
- 파일 하나의 크기는 10MB로 제한한다. 큰 산출물은 첨부하지 않고 위치를 본문에 적는다.
- 관찰 근거의 본문은 계속 필수다. 본문은 "무엇을 관찰했는가"라는 주장이고, 첨부는 그 주장을 뒷받침하는 자료다.
- 화면은 첨부 상태를 `보존됨`(해시 일치), `변경됨`, `없음`으로 보여 준다.
- `backup <대상>`은 첨부 폴더를 `<대상>.artifacts/`로 함께 복사한다.
- 폴더 없는 작업 공간에서는 DB 파일 옆의 `<DB 이름>.artifacts/`를 사용한다.

## 6. 화면에서 파일 열기

- 앱은 projection이 계산한 절대 경로나 URL만 연다.
- 실행 파일 확장자(`.exe`, `.bat`, `.cmd`, `.ps1`, `.msi`, `.lnk`, `.vbs`, `.js`, `.com`, `.scr` 등)는 실행하지 않고, 탐색기에서 해당 파일을 선택한 상태로 보여 준다.

## 7. `ui-projection` v10

- 목표, 접근안, 과제마다 `references`: `{id, location, label, actor, resolved, exists}`
- 관찰 근거마다 `attachments`: `{name, sha256, size, path, status}`
- 최상위에 `project_root`(없으면 `null`)

## 8. 범위에서 제외

- 관찰 근거 정정에 첨부를 붙이는 기능은 실제로 필요해질 때 추가한다.
- 문서 내용을 특정 시점으로 고정하는 링크(Git 커밋 해시 등)는 이 저장소를 Git으로 관리하기 시작한 뒤 검토한다.
- 다른 프로젝트용 전역 설치와 배포는 dogfooding 이후에 다룬다.
