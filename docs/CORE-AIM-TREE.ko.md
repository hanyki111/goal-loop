# 하위 목표(Aim 트리) 설계

상태: 합의됨, 구현 완료(2026-10-04, `ui-projection` v11)
근거: dogfooding 시작 전 논의. 「게임을 만든다」처럼 큰 목표를 나눌 방법이 없었다.

## 1. 구분 기준

**완료 기준(범위·성공 기준·검증 방법)을 쓸 수 있으면 과제로 나누고, 아직 쓸 수 없으면 목표로 나눈다.**

- 목표 트리는 **방향**을 나눈다. 예: 「게임을 만든다」 → 「전투가 재미있다」, 「첫 스테이지를 끝까지 할 수 있다」
- 과제 트리(Goal Tree)는 **실행 약속**을 나눈다. 예: 「적 AI 구현」 → 「길 찾기」, 「공격 판단」

## 2. 규칙

| 항목 | 규칙 |
|---|---|
| 부모 | 하나만 둔다. 순환은 거절한다 |
| 연결 시점 | 만들 때(`aim-create --parent`) 또는 나중에(`aim-parent-add`) 한 번 연결한다. 연결은 바꾸지 않는다 |
| 부모의 상태 | 진행 중(`open`)인 목표만 부모가 될 수 있다 |
| 자동 달성 | 없다. 하위 목표를 모두 달성해도 상위 목표는 별도의 목표 달성 평가가 필요하다 |
| 상위 목표의 달성 평가 | 유효한 검증 판단 또는 **직접 하위 목표의 유효한 달성 평가**를 하나 이상 인용한다 |
| 상위 목표를 멈추거나 그만두면 | 하위 항목을 자동으로 닫지 않는다. 실행 허용 단계에서 상위 목표들의 상태를 확인해, 그 아래의 새 접근안·과제 확정·실행을 막는다 |
| 상위 목표의 과제 | 상위 목표에도 직접 접근안과 과제를 둘 수 있다(통합 확인처럼 상위 수준의 일) |

두 단계 기준을 적용하면, 부모 연결은 계산할 수 없는 새 사실이므로 기록한다. 또한 실행 허용과 달성 판단에 영향을 주므로 Core가 강제한다.

## 3. 검토 전파

하위 목표의 달성 평가가 관찰 근거 정정으로 재검토 상태가 되면, 그 평가를 인용한 상위 목표의 달성 평가도 같은 영향 검토에서 재검토 상태가 된다. 상위 평가는 인용한 검증 판단과 하위 평가가 모두 유효할 때만 유지(reaffirm)로 유효 상태에 돌아간다. `next`는 인용한 기록의 검토가 끝난 뒤에 상위 평가의 검토를 제안한다.

## 4. 인터페이스

```powershell
goal-loop aim-create "전투가 재미있다" --parent aim-1
goal-loop aim-parent-add aim-3 aim-1
goal-loop aim-evaluate aim-1 "owner" "결론" aim-evaluation-2 aim-evaluation-3 verdict-7
```

- `aim-evaluate`의 인용 목록에는 `verdict-*`와 `aim-evaluation-*`를 섞어 쓸 수 있다.
- `ui-projection` v11: 목표에 `parent_aim_id`, 그래프 연결 `aim-parent`, 달성 평가에 `child_evaluation_ids`
- `next`: 상위 목표에 인용할 수 있는 유효한 하위 평가나 검증 판단이 있으면 달성 평가를 제안한다. 하위 목표가 있는 목표에는 "접근안이 없다"는 제안을 하지 않는다.

## 5. 화면

- 왼쪽 목록과 그래프에서 하위 목표를 상위 목표 아래에 보여 준다.
- 목표 화면에 「하위 목표」 영역(목록과 「＋ 하위 목표 추가」)과 상위 목표 링크를 둔다.
- 달성 평가 폼은 인용할 검증 판단과 하위 목표의 달성 평가를 함께 보여 준다.

## 6. 범위에서 제외

- 여러 부모, 연결 변경·해제
- 하위 목표를 모두 달성했을 때의 자동 제안 이상의 자동화
